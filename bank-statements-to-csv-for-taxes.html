Bank statements to CSV for taxes: one year in one checked file

At tax time you usually need the same thing: every transaction for the year, in one spreadsheet, with a category next to each line. Your accountant asks for it, your tax software can import it, and you want to be sure nothing is missing. Here's a way to build that file from twelve PDF statements without retyping anything.

1. Collect the right statements

Download every monthly statement that touches the tax year, plus one on each side. A statement dated January 3 often covers mid December, and the January statement of the next year can hold late December rows. You'll trim the extra rows at the end, by date.

If your bank still offers a CSV download for the whole year, take it and skip to step 3. Most banks only keep 90 days to 18 months of downloadable activity, so for older periods the PDF is what you have.

2. Get the rows out of each PDF

  • Excel (Microsoft 365, Windows): Data → Get Data → From File → From PDF, pick the transaction table, and repeat per file. Use Append Queries to stack the months.
  • Tabula (free): draw the table area once per layout and export each statement to CSV.
  • A converter: faster for twelve files, but check its output the same way as below. A tool that reads a 6 as an 8 still gives you a tidy spreadsheet.

3. Use one simple layout

Keep five columns and nothing else. Tax software and accountants both handle this shape well:

Date        Description                 Amount    Balance    Category
2025-01-03  CARD 4411 OFFICE SUPPLY      -84.20   3,912.55   Office
2025-01-05  TRANSFER FROM CLIENT A     1,500.00   5,412.55   Income

Two rules make the file safe to import:

  • One signed amount column. Money in positive, money out negative. If the PDF has separate debit and credit columns, use =C2-B2 (credit minus debit) and keep only the result.
  • Dates as ISO text (2025-01-03) when you save to CSV. A file that says 03/01/2025 means March to one program and January to another. In Excel, format the column as yyyy-mm-dd before you save.

4. Check every month before you categorize

Categorizing a file with a missing row means doing it twice. Each statement prints an opening and a closing balance, so check each month on its own. With the month's amounts in column C:

= opening_balance + SUM(C2:C40) - closing_balance     → should be 0.00

If the statement prints a running balance on each line, you can go further and check every row: =ROUND(D2+C3-D3,2) next to row 3, filled down, should be zero all the way. The first non-zero line is where a row was dropped, doubled or misread. The free reconciliation template has this check built in.

5. Remove the overlap

Statements that share days at the edges give you duplicate rows when you stack them. Don't use Remove Duplicates on date and amount alone: two real coffee purchases of 4.50 on the same day would be merged. Compare date, description, amount and running balance together. Two genuine rows almost never share the same balance after them; a duplicate always does.

Then filter to the tax year (Date >= 2025-01-01 and <= 2025-12-31) and delete the rest.

6. Add categories

Add a Category column and fill it with whatever your accountant or tax form uses. A small rules table saves most of the work: put keywords in one column (OFFICE, UBER, RENT) and categories in the next, then use SEARCH inside IFERROR or XLOOKUP with wildcards to fill matches. What's left you categorize by hand. Which categories matter, and what counts as deductible, depends on where you file. Your accountant decides that part; the file just has to be complete and correct.

A pivot table by Category and month gives you the totals most people actually send. Keep the full row list as a second sheet in case someone asks about a single line.

7. Save the CSV

File → Save As → CSV UTF-8. UTF-8 keeps accented names in descriptions readable. Open the CSV in a text editor once to confirm the amounts use a dot for decimals and no thousands separators, which is what most importers expect.
