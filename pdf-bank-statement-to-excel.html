How to convert a PDF bank statement to Excel (3 free ways) and prove it's right

Retyping a statement is slow. Copy-pasting a PDF table into Excel usually turns every row into one long cell. Here are three free methods that work, ranked by effort, plus the check most guides skip: a single formula that proves no transaction was dropped or misread.

Method 1: ask your bank for CSV (best when available)

Most online banking sites can export recent transactions as CSV, Excel, OFX/QFX or QBO under "Download", "Export" or "Statements". This is the most accurate source because nothing has to be read off a PDF. Two limits:

  • Many banks only export the last 90 days to 2 years, and not closed accounts.
  • If a client or a lender sends you PDFs, there's nothing to export.

Method 2: Excel's built-in PDF import (Power Query)

Excel for Microsoft 365 on Windows can read tables straight out of a PDF:

  1. Open a blank workbook → Data tab → Get Data → From File → From PDF.
  2. Pick the statement. The Navigator lists every table and page it detected (Table001, Page001…).
  3. Select the transactions table, then click Transform Data to fix types: set the date column to Date (use Using Locale if your bank writes 31/01/2026), and amounts to Decimal Number.
  4. If the statement continues over several pages, you'll get one table per page. Use Append Queries to stack them.
  5. Close & Load.

Watch out for: wrapped descriptions that become extra rows, "Balance brought forward" lines inside the table, and banks that print the date only once per day (the other rows of that day come in with a blank date, so fill them down with Transform → Fill → Down).

Method 3: Tabula (free, open source, any OS)

Tabula is a free desktop tool made for pulling tables out of text-based PDFs. Load the PDF, drag a box around the transaction table on each page (or use Autodetect Tables), preview it with the Stream method, and export to CSV. It works well on clean layouts and needs the same clean-up as Power Query.

None of these methods work on scanned statements (photos of paper). For those you need OCR. Run any OCR result through the check below, because OCR misreads digits.

The 1-minute check: prove every row is right

Your statement already contains the answer key: an opening balance, a closing balance and usually a running balance on each row. Put amounts as signed numbers (money out negative) in column C and the printed running balance in column D, starting at row 2, with the opening balance in D1. Then in E2:

=IF(ROUND(D1 + C2 - D2, 2) = 0, "OK", "CHECK")

Fill it down. Every row should say OK. A CHECK means that row (or one just above it) was misread, dropped or duplicated. Finally confirm the totals:

= opening_balance + SUM(C:C) - closing_balance     → should be 0.00

If the bank prints no running balance, the total check alone still catches most problems.
